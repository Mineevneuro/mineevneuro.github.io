spine-unit-lab

An open test bench that recreates the digital workflow of a spine department on an open-source stack, with AI as an assistant to the surgeon, not a decision maker.

Stack
FHIR server with synthetic patients (Synthea), Orthanc PACS (DICOM), nnU-Net / TotalSegmentator, RAG, LLM agent
Status
Architecture and module contracts defined; first module (trajectory planner) next

Research and educational project. Not a medical device and not for clinical use. Synthetic or open data only.

Clinical context

In a real department the information for one surgical decision is scattered: images in PACS, history and labs in the EHR, guidelines in PDFs, measurements in the surgeon's head. The project asks a practical question: which parts of that work can AI take over reliably, and how do you prove it?

Approach

The bench reproduces one patient journey:

  1. Patient admitted → record created in the EHR (FHIR).
  2. MRI / CT ordered → study stored in PACS (DICOM).
  3. Images segmented → measurements extracted (canal, discs, pedicles).
  4. Agent combines measurements, history and guidelines → draft for the surgeon.
  5. Surgeon reviews, edits and signs. AI never writes to the chart on its own.

Design rules

  • Contracts first: JSON schemas are written before the code that produces or consumes them.
  • No real patient data: synthetic (Synthea) and open datasets only.
  • Human in the loop: every AI output is a draft with sources and confidence.
  • Security by design: threat model before features; security and AI-safety tests only against this bench.
